# Students / athletes (verified 2026-11-09)

Code: `src/app/dashboard/students/*`, `src/components/students/*` (data-table, dialog, bulk-upload), parent side in `parent-portal.md`.

## Who creates athletes
- **Parent** via the join link (`createChildAsParent`, `students.parent_id` set).
- **Coach** manually (`createStudent`, `coachAddManualStudentAndEntry`) or by Excel/CSV import (`student-bulk-upload.tsx`, `xlsx` 0.20.3 from the SheetJS CDN). `parent_id` is NULL.

## Fields (see db-schema.md)
name, gender (`male|female`), date_of_birth, weight, rank, photo_url, phone, school_or_city, `registration_no` (auto), `is_active` (trigger), consent_*, `membership_status`.
Ranks: white, yellow, orange, green, blue, brown_3, brown_2, brown_1, black_1, black_2, black_3.

## Rules
- `registration_no` is generated by trigger: `SK<yy>-<n>`. Never set manually (except bulk loads on a DB without migration 002).
- `is_active` is recomputed by `evaluate_activity_on_entry` from the last two events the dojo took part in.
- Coach roster table: client-side TanStack table + fuse.js search; keep server queries paginated (10k athletes total, ~10 per dojo average).
- Bulk import template headers: Name, Gender, Rank, Weight, Date of Birth (`student-bulk-upload.tsx`; soft validation of rank/weight; Excel parsed in the browser with `xlsx` 0.20.3 from cdn.sheetjs.com — not the npm 0.18.5 build).
- `dob_locked` exists in the schema but is never written or enforced (known-issues).
